# E13：新闻时间对齐、去重与线性残差对照

主线继续优先改进行情和财报。E12 的训练误差下降而开发误差上升，这一轮先以低容量模型排查新闻处理问题，检验新闻是否值得进一步投入。保留历史实验代码和结果，不改变 E10-B 的权重、财报特征及标准化统计量。

## 运行

```bash
python -m experiments.gru_e13.train --device cuda
```

一次命令完成三组对照，默认自动在 holdout 上评估开发集选出的真实新闻残差模型，同时报告原 E10-B。不是多轮 GRU 训练：E10-B 对训练集、开发集分别推理一次，随后对缓存于内存的残差拟合小型线性模型。GPU 主要用于 E10-B 推理，PCA、聚合和线性拟合使用 CPU。

仅统计新闻处理情况：

```bash
python -m experiments.gru_e13.train --audit-only
```

小样本检查（训练 512 条、开发 256 条，不评估 holdout；文件写到独立的 `smoke/`）：

```bash
python -m experiments.gru_e13.train --device cpu --smoke-test
```

只做开发集选择可加 `--skip-holdout`；之后运行以下命令，直接加载保存的预处理统计量、残差参数和冻结基座，不重新拟合：

```bash
python -m experiments.gru_e13.train --device cuda --evaluate-holdout
```

## 新闻处理

1. 同一股票的相同 `vector_id` 只保留最早发布时间。不同股票与同一篇新闻的关联保留。不使用语义相似度合并，也不保证不同编号的相似文本已去重。
2. 每个交易日设置一个信息截止点，新闻归入“不早于发布时间的第一个截止点”。默认 `23:59:59`，与原始读取器的输入末日规则一致。例如周六、周日新闻归入周一；它们不会进入周五的预测。
3. 默认允许输入末日当天的盘后新闻。若实际任务要求收盘时预测，可单独使用 `--cutoff-time 150000`，此时 15:00 后新闻进入下一个交易日区间。两种信息截止条件应分别报告，不混作同一实验。
4. 最近 1、5、20 个交易日区间分别提取新闻向量均值、`log1p(篇数)`、有新闻区间比例、距离最近新闻的交易日区间数的 `log1p`。均值按新闻篇数加权，不使用逐维最大池化。
5. PCA 只从实际训练特征窗口包含的去重新闻拟合，默认最多抽取 50,000 篇，将 512 维压至 16 维。不使用开发或 holdout 新闻拟合；统计量保存到检查点。

区间的含义是“上一个交易日截止点之后，到本交易日截止点为止”。特征只取输入末日及更早的区间，不读取目标期新闻。最近 20 个区间都无新闻时，修正严格为零。对于当前 96 日输入，所取最近 20 个区间都处在输入日期范围内。

## 三组对照

| 分组 | 特征 | 目的 |
| --- | --- | --- |
| `metadata_only` | 3 个窗口 × 3 项数量、覆盖、新鲜度信息，共 9 维 | 新闻活跃程度是否有用 |
| `real_content` | 9 维元信息 + 3 × 16 维真实向量，共 57 维 | 新闻内容是否带来额外收益 |
| `shuffled_content` | 元信息不变，向量内容随机重配，共 57 维 | 改善是否依赖正确的新闻内容 |

打乱对照在训练新闻向量库内置换内容。未在训练窗口出现的新闻编号也只随机关联到训练库向量。映射按新闻编号和随机种子固定，各股票、各数据切分一致；发布时间、数量、缺失掩码完全不变，不借用未来验证新闻给训练样本提供内容。它是破坏新闻内容对应关系的对照，不能单独作为统计显著性的证明。

## 残差模型与选择

```text
训练残差 = 原始标签 y - 冻结 E10-B 的预测
最终预测 = 冻结 E10-B 的预测 + 线性新闻修正
```

`y` 继续采用每只股票训练期固定均值、标准差得到的标准化 Close，输出仍为 `[B, 24]`。不引入行情隐藏状态，近期无新闻时将修正强制为零。

每组用训练集统计量标准化特征，对每个预测步分别拟合 Ridge：

```text
mean_samples((predicted_residual_h - true_residual_h) ** 2) + alpha * sum(weights_h ** 2)
```

偏置使用“近期有新闻”这一掩码列实现，也受正则化。默认 `alpha = 0.01, 0.1, 1`，每组仅按开发集 MAE 选择，MSE 用于同分比较。**这与此前 GRU 的 MAE + 0.2 MSE 训练目标不同**，用于简单诊断新闻信号；性能差异不能全部归因于时间对齐或去重。本实验也未单独拆分这两项处理的因果贡献。

不使用早停，因为线性模型直接求解。保存并评估最佳训练后的真实新闻模型，即使它不如 E10-B，也不会悄悄退回无新闻基座。仅该模型与 E10-B 进入默认 holdout 报告，两组控制只报告开发指标。

输出：

- `result.json`：三组最优开发指标，以及真实新闻模型和基座的 holdout 指标。
- `development_search.json`：全部正则化系数的开发指标。
- `development_windows.json`：基座与三组残差模型在开发集三个时间段的指标。
- `news_audit.json`：去重、时间归属和训练 PCA 可用新闻数量；新闻总量统计覆盖该数据集股票的完整历史，不限训练日期。
- `progress.json`：运行中的基座推理进度，成功结束后删除。
- `checkpoints/best.pt`：真实新闻残差模型、预处理统计量和冻结 E10-B 权重。

三个开发时间段是固定模型的分时段诊断，并非独立滚动重训练。holdout 沿用已有的时间隔离切分，不参与 PCA、残差拟合或超参数选择；由于此前已反复查看，其结果应作为辅助证据。

如果真实内容未稳定优于 E10-B、元信息和打乱对照，暂停继续扩展新闻架构，优先推进财报可用时间/缺失值处理，以及行情和财报模型的稳健性。若真实内容有效，再考虑受约束的非线性模型；不直接据此增加复杂融合结构。

行情和财报主线也不以继续堆叠 GRU 为默认方向：先检查财报公告时点（目前是报告期末加 30 日的近似，不能保证所有财报都已公开），再对照逐字段缺失掩码、正确的单季度/同比口径与少量经济含义明确的特征。E11 已说明直接扩大比例和变化特征集并不一定改善效果。最后再考虑小规模行情骨干对照；所有选择优先看开发指标和跨时段一致性。
